## 1. 代码事实：旋转参考系如何被模拟

游戏世界坐标实为**实验室参考系**。旋转参考系由两部分"构造"：

1. **力**：对玩家施加向心加速度 `-ω²R`（由"圆盘"提供），使玩家绕核心做圆周运动；
2. **视觉**：`_update_rot_visual()`（`Player.gd`）玩家与摄像机整体随盘旋转（Model B：转盘屏显静止、角色屏显固定）。

状态机（`rot_state`）：

- `ROT_NONE`（横向）/ `ROT_SWITCHING`（切换洞察）/ `ROT_SYNCED`（已同步）。
- 进入切换：`_update_insight`（L287-296）要求"按 Shift 时处于核心影响范围内，且上次按下在范围外"（前沿触发）；切入后 `Engine.time_scale = 0.2`，无限时。
- 同步成功：`_on_synced`（L330-344）把 `velocity` **直接改写为 `disk_v`** 并设 `rot_sync_lock = 1.0`（1 秒内 `a_abs` 强制为 `-ω²R`，拒绝输入）。
- 脱离：`r > influence_radius` → `_exit_rotating`（L186-187, L347-357）。

关键公式（`_rotating_physics` L143-187）：

```
disk_v = (-ω·R.y, ω·R.x)          # 圆盘切向速度
v_rel  = velocity - disk_v          # 相对圆盘的速度
a_input = (r̂·input.y·radial + t̂·input.x·tang) / η   # 玩家输入（W/S径向、A/D切向）
a_cent  = ω²·R                       # 离心
a_cor   = (2ω·v_rel.y, -2ω·v_rel.x)  # 科里奥利
a_abs   = a_input                     # ROT_SWITCHING
        | a_input - ω²R (+安全环弹簧) # ROT_SYNCED
        | -ω²R（ROT_SYNCED）/ ZERO（ROT_SWITCHING）当 rot_sync_lock > 0
velocity += a_abs·delta；position += velocity·delta   # 手写积分，无 move_and_slide
```

**关键事实：离心与科里奥利（虚假力）从不进入 `a_abs`**，只经 `IllusionManager.set_rot_inertia(a_cent + a_cor)` 写入 `current_fake_vector`，供：洞察红色虚线显示、幻灵方块受力（`PhantomBlock._integrate_forces`）、星空漂移（`StarField`）、HUD G 值。

场景参数：

- `Main.tscn`：ω=0.8，influence_radius=220，core_radius=150；玩家 radial/tang=60，sync_radius=30，safe_ring=0，max_speed_x=140。
- `Stage3.tscn`：ω=1.0，influence_radius=10000（全关）。

## 2. 各参考系受力明细（Q1/Q2 结论）

### 2.1 横向参考系（ROT_NONE）

- 施加：`input·speed/η + fake_force - damping·velocity`（+ 跳跃重力，落地由 move_and_slide 抵消）。
- 洞察显示（v0.2）：蓝=输入（`input_dir·speed/η`）、红=虚假力、绿=系统阻力（阻尼 + 空中重力），同比例缩放（ARROW_SCALE=1.0，[8,150]px）。
- **v0.2 已实施**：绿=阻尼+空中重力（替代原固定 40px 重力箭头）；箭头同比例，合力=运动可验证。

### 2.2 切换中（ROT_SWITCHING）

- 施加：**只有 `a_input`**。无向心力、无阻尼、无虚假力。进入时 `velocity` 不重置 → 初始 `v_rel` 大。
- 旋转系内观察到的加速度：`a_rot = a_input + ω²R + a_cor`（= 蓝 + 红）。
- 洞察显示：金（目标向心力）+ 蓝（输入）+ 红虚线（惯性力）+ **紫（合力=蓝+红）**，同比例缩放（ARROW_SCALE=1.0，[8,150]px）。
- **v0.2 已实施**：紫=合力（旋转系内实际加速度方向）。

### 2.3 已同步（ROT_SYNCED）

- 施加：`a_input - ω²R`（+ 安全环弹簧，当前未启用）；同步锁定 1 秒内强制 `-ω²R`。
- 旋转系内观察到的加速度：`a_rot = a_input + a_cor`（离心被施加的向心力抵消）。
- 洞察显示：蓝（输入）+ 红虚线（惯性力）+ **绿（系统阻力=圆盘向心力 `-ω²R`）**，同比例缩放。
- **v0.2 已实施**：绿=系统阻力。没有绿时，红里含的离心看起来"该甩人却不动"——这正是"核心引力看不到"困惑的来源。

## 3. 现象 A：真·静止可达，且无简谐（Q3/Q4 更正后结论）

- **可达**：切换态 `a_abs = a_input`，输入归零后 `a_abs = 0`，惯性保持静止 → **世界位移 = 0**。旋转核心中心不动（只自转），可作锚点。
- **转盘显示真实角速度**：`RotatingCore._process` 的 `rotation += omega·delta` 即物理 ω。真静止时（Model B 摄像机随盘转）转盘指示线/公转小点屏显静止、核心绕玩家转——这是旋转系内的正确相对表现；读转速以核心自转（每秒 ω）为准。✓
- **无简谐的原因**：`-ω²R`（恢复力）只在 `ROT_SYNCED` 施加；而同步态强制 `v = disk_v`，不可能实验室系静止。故"真静止"只存在于切换态，而切换态无任何自动力 → 静止保持静止。

## 4. 现象 B：同步态"径向加速 → 离心运动 → 释放后轻微简谐"（Q4 补充）

### 4.1 推演

设玩家已同步（`v_rel = 0`，精确圆周）：

1. **径向加速（W/S）**：`a_rot = a_input + a_cor`，初始 `a_cor ≈ 0` → 沿 r̂ 直线加速，即"离心运动"（S=远离核心，W=靠近核心）。随径向速度增大，科里奥利把运动向切向偏转（逆旋转方向）。→ **W/S 改变轨道半径的玩法成立（游玩/关卡设计合格）**。
2. **释放输入后**：残留径向速度 `v_r`。此时 `a_abs = -ω²R`（同步态空闲力），即

   ```
   d²R/dt² = -ω²·R
   ```

   一个**无阻尼二维简谐振子**（频率 ω，周期 2π/ω）。通解：

   ```
   R(t) = R0·cos(ωt) + (V0/ω)·sin(ωt)
   ```

   - 若 `V0 = disk_v`（精确同步）→ 精确圆周，无简谐；
   - 若 `V0 = v_r·r̂0`（纯径向残留）→ R(t) 始终沿 R0 方向，**沿过核心的直线做 1D 简谐**（穿过核心），旋转视角下表现为**半径周期性伸缩** = 轻微简谐运动；
   - 一般切向偏差 → 椭圆轨道（半径呼吸）。

3. **根因**：同步态力模型 `a_abs = -ω²R` 本身是线性恢复力，且旋转物理**无任何阻尼**——任何偏离 `disk_v` 的速度扰动都导致**永不衰减**的振荡（非数值误差；半隐式欧拉对此稳定，不耗散也不发散）。

### 4.2 对需求 1 的意义

该模型下**合力确实产生了对应运动**（需求 1 在物理层成立：力 = -ω²R ⇔ 运动 = 简谐/椭圆）。问题是**行为不驻留**：释放径向输入后玩家不会"停在新的轨道半径"，而是振荡。这是**设计决策**而非物理错误：

- 选项 B1：同步态加"相对阻尼"（如 `-k·v_rel`，摩擦/贴合圆盘语义）→ 扰动衰减、自然驻留于当前半径（推荐，贴合"站在圆盘上"直觉）；
- 选项 B2：维持无阻尼 SHO（物理"正确"但玩家无法停稳）；
- 选项 B3：启用/设计安全环弹簧（`safe_ring_radius`）把玩家拉回特定半径（现值为 0）。

> **决策（v0.2）**：采用 **B2**——同步态维持无阻尼 `-ω²R` 模型（合力=运动的物理自洽优先）。"轻微简谐"是该模型的必然现象，**不引入额外阻尼**（游戏内行为不变）。

## 5. 现象 C：视觉锚点漏洞（摄像机旋转叠加）

### 5.1 根因（代码事实）

- `_update_rot_visual`（L430-447）：
  - 玩家节点 `rotation = _rot_vis_rot`，目标 `ang - π/2`（脚指向核心，`ang = (core-player).angle()`）；
  - 摄像机 `_rot_camera.rotation = _rot_vis_cam`，目标 `ang + π/2`（想把核心固定屏幕正上方）。
- 但 `Camera2D` 是 **Player 的子节点**（`Main.tscn` L97 `[node name="Camera2D" parent="Player"]`），2D 旋转沿父子链**相加**：

  ```
  摄像机全局旋转 = 玩家旋转 + 摄像机局部旋转 = (ang-π/2) + (ang+π/2) = 2·ang
  ```

  设计意图的全局目标应为 `ang + π/2` → **当前实现旋转量翻倍且组合方向错误**。

### 5.2 屏显后果（已同步，ang 以 -ω 变化）——v0.1 缺陷行为，v0.2 已由 Model B 修复

- 角色精灵屏显转速 = `(ang-π/2) - 2·ang = -ang-π/2` → **以 +ω 在屏幕上自转**（"相对静止时人物仍在转"）；✓ 与观察一致
- 核心**不在**屏幕正上方，反而以 +ω 绕玩家公转；
- 转盘指示线屏显转速 = `ω - 2·(-ω) = 3ω`。
- 真静止时：一切冻结，转盘屏显 = ω（正确）。

### 5.3 修复方案（已决策：Model B，v0.2 已实施）

- **Model A（未采用）**：摄像机全局 = `ang + π/2`，核心固定屏幕正上方、角色屏显固定（脚朝向核心）。副作用：同步后转盘屏显 = **2ω**（角色为面向核心而逆旋），与"踩在盘上应看到盘静止"的直觉冲突。
- **Model B（已采用）**：玩家与摄像机**整体**追踪 `core_ref.rotation`（随盘旋转）。
  - 同步后：转盘指示线/公转小点屏显静止、角色屏显固定（不因公转而自转）✓；**核心屏显位置固定（不绕转）**——修正 v0.1 的说法：只有**未同步**（切换/真静止）时核心才绕玩家转，这正是相对运动反馈；
  - 实现：`rotation → core_ref.rotation`；摄像机是玩家子节点、2D 旋转沿父链相加 → `_rot_camera.rotation = _rot_vis_cam − _rot_vis_rot`（两者同向同速收敛，局部≈0）；
  - 附加：旋转系内**禁用摄像机位置平滑**（保证转盘/核心屏显精确静止）；滚轮缩放视野（0.8 × 用户倍率）。
